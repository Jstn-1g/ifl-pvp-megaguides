# Security policy

## Supported code

Security fixes are applied to the current default branch and current `iflpvp.com` deployment when the affected behavior originates in this project. Historical releases, forks, local modifications, and archived content are not supported separately.

## Report a vulnerability privately

Do not report suspected vulnerabilities in a public issue, pull request, discussion, social post, or guide-correction form.

After public creation, use GitHub private vulnerability reporting for this repository. If that channel is unavailable, email `support@iflpvp.com` with the subject `Security report: IFL PvP MegaGuides`.

Include, where safe:

- affected URL, branch, commit, or file;
- concise impact and reproduction details or a minimal proof of concept;
- browser, operating system, and relevant configuration; and
- a safe contact method.

Never include real credentials, session cookies, API keys, private user data, or unrelated personal information.

## Research boundaries

Good-faith research must not access, modify, retain, or disclose data that is not yours; disrupt the site or an external service; use denial-of-service, spam, social engineering, credential attacks, or physical attacks; test a third-party service merely because the project references it; upload malware; or continue after collecting the minimum evidence needed to explain the issue.

Use a local checkout whenever possible. Stop and report if testing could affect another person or external service.

## Expectations

We will make a good-faith effort to acknowledge complete reports within five business days and to keep reporters informed of material progress. We do not promise a bug bounty. Coordinated disclosure and optional reporter credit are welcome when safe.

Copyright, attribution, and takedown requests are not security reports. Use [NOTICE.md](NOTICE.md).
